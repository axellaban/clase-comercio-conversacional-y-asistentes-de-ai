Guardrails — Los Límites del Agente

Un agente sin guardrails es una bomba de tiempo. Definís hasta dónde llega la autonomía.

Guardrails de Seguridad

  • Stock: No ofrecer productos sin confirmar disponibilidad en DB
  • Descuentos: No aplicar descuentos sin autorización explícita en el prompt
  • Datos del cliente: No pedir ni almacenar info sensible fuera del CRM
  • Loop detection: Máximo 3 turnos sin resolución → HITL obligatorio

Guardrails de Marca

  • Tono: El agente habla como la marca — ni más formal, ni más relajado
  • Idioma: Mantener el mismo idioma que usó el cliente
  • Temas off-limit: Política, religión, competidores — redirigir siempre
  • Longitud: Mensajes de máx. 3-4 líneas. WA no es email.
# En el System Prompt — sección de guardrails
RESTRICCIONES ABSOLUTAS:
- Si stock del producto = 0 → NO confirmes disponibilidad. Ofrece alternativa o HITL.
- Si la canasta supera $[UMBRAL_TICKET] → emite flag ESCALATION_REQUIRED y detenete.
- Nunca apliques descuentos sin que el campo "descuento_autorizado" = true en el contexto.
- Si el usuario usa palabras de frustración (enojo, queja, devolución) → HITL inmediato.

# TÁCTICAS DE VENTA MULTI-TURNO
1. Descubrimiento: hacé 1 pregunta de contexto de uso antes de recomendar.
2. Anclaje: ofrecé cuotas ANTES de aplicar descuento. No descuentes automáticamente.

De Copilot a Autopilot

La decisión más importante antes de poner tu agente en producción.

🧑‍✈️ Copilot — Empezamos acá siempre

  • El agente propone — el humano aprueba y ejecuta.
  • Draft listo → humano revisa → humano envía.
  • Riesgo bajo. Ideal para el primer lanzamiento.
  • Genera los datos que necesitamos para confiar en el sistema.

🤖 Autopilot — Llegamos acá con datos

  • El agente propone Y ejecuta solo.
  • Nadie revisa — el sistema actúa autónomamente.
  • Solo para procesos ya validados con métricas reales.
  • Requiere >95% de precisión sostenida en ese proceso.
Regla: Empezamos en Copilot. Pasamos a Autopilot cuando los datos muestran >95% de decisiones correctas para ese proceso específico. No antes. El "shadow mode" del checklist es exactamente esto.

y del ebook "El Gran Recetario Plant-Based".

y entregar el link de descarga cuando corresponda.

Simpático, alegre, empático. Cálido y divertido.
Usá emojis naturales 🐾🌿💚. Cerrá con gratitud.
Usá siempre tuteo: "cuéntame", "quieres".

# REGLAS CLAVE
- No inventes precios, alias ni enlaces.
- Solo entregás el link del ebook si recibís
  "PAGO HECHO" + el email del comprador.
- Si dicen "MUESTRA" → enviá ÚNICAMENTE
  el texto exacto de la sección de muestra.
- Si hay duda de precio → ofrecé cuotas primero.
- Garantía de reembolso total, sin preguntas.

# PRECIO Y PAGO
💰 19 USD
📧 paypal.me/AXELLABANARZUBI
🔒 Sin riesgo: devolvemos si no convence.

# SECUENCIA DE VENTA
1. Ofrecé info del ebook o muestra gratuita
2. CTA: "Si quieres reservar el precio de hoy,
   decime QUIERO MI COPIA"
3. Al confirmar → datos de pago
4. Al recibir "PAGO HECHO" + email → link del ebook

🔍 Por qué cada decisión

  • Nombre + personalidad ("Indio el gato"): Da identidad de marca, no parece un bot genérico. Aumenta la confianza.
  • "PAGO HECHO" + email como trigger: Guardrail manual anti-fraude. El agente no entrega el link sin confirmación explícita.
  • Texto EXACTO para la muestra: Evita que el LLM improvise y altere la experiencia del onboarding.
  • Cuotas antes de descuento: Guardrail de margen — el agente nunca negocia precio sin autorización.
  • Garantía sin preguntas: Elimina la objeción de riesgo antes de que aparezca, sube conversión.
💡 Para la clase: Este prompt es un caso real y funcional. Podés mostrar una conversación en vivo y los alumnos ven exactamente cómo responde Indio a cada intención.

Caso Aparte: RAG de Stock + Manual

HolaVeggie no tiene catálogo de stock. Este es el mismo flujo aplicado a un retailer con inventario dinámico.

File Search como base de conocimiento

Google File Search indexa PDFs con descripciones de productos, políticas de cambio, info de marcas. RAG semántico sin infra.

Documentos indexados:
  • Catálogo de productos con descripciones
  • Políticas de cambio y devolución
  • Guías de tallas y materiales
  • Info de marcas y colecciones

El agente busca info del producto en File Search: "las Nike Air Force son de cuero premium, disponibles en 5 colores..."

Google Sheets para datos dinámicos

Stock, precios, y disponibilidad en tiempo real. El agente consulta antes de confirmar.

// Google Sheet: productos
SKU         | Producto       | Talle | Stock | Precio
NK-AF-42-W  | Nike AF1 White | 42    | 3     | $120
NK-AF-43-W  | Nike AF1 White | 43    | 0     | $120
AD-SB-42-B  | Adidas Samba   | 42    | 8     | $95

// n8n consulta el sheet filtrando por SKU o producto
→ Devuelve stock real + precio actual

Flujo combinado: File Search da la info del producto ("material, colores, fit") + Sheets da stock/precio → el agente responde con data completa y actualizada.

¿Por qué esta arquitectura? File Search = zero infra, solo subís PDFs. Sheets = fácil de actualizar por cualquier persona del equipo, sin tocar código. Mismo patrón que Reglas de Golf: RAG para conocimiento estático + fuente dinámica para datos que cambian.

  • Convierte el estado técnico en lenguaje natural cálido
  • Si hay demora → alerta al equipo de logística Y notifica al cliente proactivamente

Críticos — No lanzar sin estos

Optimización — Primeras 4 semanas

  • A/B testing de System Prompts (tono formal vs. cercano)

Rollout gradual: No desconectes el equipo humano el día 1. Arrancá en Copilot / shadow mode — el bot responde y el humano revisa — durante la primera semana. Pasás a Autopilot cuando los datos muestren >95% de precisión.

El Puente al Programa de Agentes

Lo que construyeron hoy: Un agente reactivo — responde cuando el usuario inicia.
Lo que viene en el programa de Agentes: Agentes proactivos y autónomos — que monitorean, deciden y actúan sin esperar que nadie les escriba.

Este flujo de n8n que armaron hoy es exactamente la base sobre la que se construye eso. El System Prompt, el RAG, el HITL — todo eso lo van a ver de nuevo en el siguiente programa, pero operando de manera autónoma y con múltiples agentes coordinados entre sí.
