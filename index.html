Sin RAG vs. Con RAG: por qué importa

El agente sin contexto propio inventa — con el mismo tono seguro que cuando tiene razón. Una sola venta fantasma destruye más confianza que cien ventas perfectas.

❌ Agente SIN RAG

  • Responde desde entrenamiento obsoleto.
  • Inventa stock, precios y políticas con total seguridad.
  • No puede citar fuentes — no tiene de dónde.
  • Destruye confianza en el primer error real.

✅ Agente CON RAG

  • Consulta tu catálogo real antes de responder.
  • Dice "no tengo esa info" cuando no la hay.
  • Confirma stock, talle y precio en tiempo real.
  • Actualizable sin reentrenar el modelo.
Objetivo de la clase: Que tu agente deje de inventar stock, precios y políticas — y empiece a responder desde el conocimiento real de tu negocio, en tiempo real.

Guardrails — Los Límites del Agente

Un agente sin guardrails es una bomba de tiempo. Definís hasta dónde llega la autonomía.

Guardrails de Seguridad

  • Stock: No ofrecer productos sin confirmar disponibilidad en DB
  • Descuentos: No aplicar descuentos sin autorización explícita en el prompt
  • Datos del cliente: No pedir ni almacenar info sensible fuera del CRM
  • Loop detection: Máx. 3 turnos sin resolución → HITL obligatorio

Guardrails de Marca

  • Tono: El agente habla como la marca — definido en el prompt
  • Idioma: Mantener el mismo idioma que usó el cliente
  • Temas off-limit: Política, religión, competidores — redirigir
  • Longitud: Máx. 3-4 líneas. WA no es email.
# RESTRICCIONES ABSOLUTAS (en el System Prompt)
- Si stock = 0 → NO confirmes disponibilidad. Ofrece alternativa o HITL.
- Si la canasta supera $[UMBRAL] → emite flag ESCALATION_REQUIRED y detenete.
- Nunca apliques descuentos sin que "descuento_autorizado" = true en el contexto.
- Si el usuario usa palabras de frustración → HITL inmediato.

El System Prompt como Vendedor

El System Prompt no describe al bot — ES el vendedor. Su estructura define si vende o fricciona.

# ROL Y OBJETIVO
Sos [NOMBRE], asesora de [MARCA]. Cálida, orientada al cierre. Hablás de vos.

# CATÁLOGO EN TIEMPO REAL [INYECTADO VÍA RAG - n8n]
{{ CATALOG_RAG_DATA }}
🚨 NUNCA ofrezcas productos con stock = 0. Si no hay stock → ofrecé alternativa disponible.

# TÁCTICAS DE VENTA MULTI-TURNO
1. Descubrimiento: hacé 1 pregunta de contexto de uso antes de recomendar.
2. Anclaje: ofrecé cuotas ANTES de aplicar descuento. No descuentes automáticamente.
3. Upsell: cuando el cliente eligió → mencioná 1 producto complementario de manera natural.
4. Mensajes cortos: máximo 3-4 líneas. WhatsApp no es un email.
5. Terminá siempre con 1 pregunta o llamada a acción clara.

# MANEJO DE OBJECIONES
- "Es caro" → destacá el valor / ofrecé cuotas / comparación de costo por uso
- "Lo pienso" → usá social proof + urgencia real (stock limitado solo si es verdad)
- "Me llega tarde" → informá tiempos reales del catálogo. No prometas sin dato.

# GUARDRAILS ABSOLUTOS (ver sección)
# HITL ROUTING
Si ticket > $[UMBRAL] o frustración detectada → emitir: {"intent":"ESCALATION_REQUIRED"}

De Copilot a Autopilot

La decisión más importante antes de poner tu agente en producción.

🧑‍✈️ Copilot — Empezamos acá siempre

  • El agente propone — el humano aprueba y ejecuta.
  • Draft listo → humano revisa → humano envía.
  • Riesgo bajo. Ideal para el primer lanzamiento.
  • Genera los datos que necesitamos para confiar en el sistema.

🤖 Autopilot — Llegamos acá con datos

  • El agente propone Y ejecuta solo.
  • Nadie revisa — el sistema actúa autónomamente.
  • Solo para procesos ya validados con métricas reales.
  • Requiere >95% de precisión sostenida en ese proceso.
Regla: Empezamos en Copilot. Pasamos a Autopilot cuando los datos muestran >95% de decisiones correctas para ese proceso específico. No antes. El "shadow mode" del checklist es exactamente esto.

RAG con File Search: Asistente de Reglas del Golf

Un asistente que responde preguntas sobre reglamento, handicaps y torneos — con RAG semántico sobre documentos oficiales usando Google File Search.

Stack de esta demo

n8n + Google File Search (RAG docs) + Google Sheets (datos dinámicos) + Gemini 2.5 Flash (agente)
Google File Search para reglamento y documentos oficiales (semántico, sin infra)  +  Google Sheets para datos dinámicos (calendar, handicaps, scores). Sin HITL — el agente resuelve todo solo.
¿Por qué este caso? Demuestra RAG puro: documentos densos + preguntas específicas + datos dinámicos. La misma arquitectura aplica a atención al cliente, soporte técnico, onboarding — cualquier caso con base de conocimiento real.

Arquitectura del Flujo RAG

El flujo genérico con File Search + datos dinámicos. Aplicable a cualquier caso de uso.

1
Trigger — Webhook recibe mensaje → normaliza: message_text, sender_id, chat_id.
2
Búsqueda RAG (Google File Search) — n8n consulta la base de conocimiento semántica con la pregunta del usuario. Si no encuentra → el agente responde "no tengo esa info".
3
Datos dinámicos (Google Sheets) — Si el caso necesita datos en tiempo real (stock, precios, calendario), n8n consulta el Sheet con los parámetros extraídos.
4
Generación — Agente genera respuesta con contexto RAG + datos dinámicos + historial de conversación. Máx. 4-5 líneas.
5
Respuesta — n8n envía la respuesta. Sin escalada humana — el agente resuelve autónomamente.
File Search = RAG sin infra: El conocimiento está en documentos indexados por Google. Subís los PDFs, File Search los indexa automáticamente, y el agente recupera los chunks relevantes. Zero config.

Checklist Pre-Lanzamiento

Críticos — No lanzar sin estos

  • RAG conectado al catálogo en tiempo real
  • IA nunca confirma stock que no existe
  • HITL activo y testeado con Chatwoot
  • Guardrails de descuentos configurados
  • Mensajes de máx. 3-4 líneas

Importantes — Primera semana

  • Personalidad del agente definida y testeada
  • Delay de 45 min en recuperación de carrito
  • Fallback para mensajes no manejados
  • WISMO verifica si el pedido ya fue entregado

Optimización — Primeras 4 semanas

  • A/B testing de System Prompts (tono formal vs. cercano)
  • Segmentación de clientes por LTV
  • Memoria multi-turno para contexto de conversaciones previas
  • Dashboard de KPIs en tiempo real
  • Revisión semanal de casos donde se activó el HITL
Rollout gradual: No desconectes el equipo humano el día 1. Arrancá en Copilot / shadow mode durante la primera semana. Pasás a Autopilot cuando los datos muestren >95% de precisión.

El puente al Programa de Agentes

En esta clase construiste agentes reactivos de ventas — responden cuando el cliente escribe.

En el programa de Agentes construís agentes proactivos y sistemas multiagente:

  • Meeting Prep Agent — trabaja a las 7 AM sin que nadie lo llame. Revisa tu calendario, investiga participantes y publica un briefing antes de la reunión.
  • Crew de agentes — múltiples IAs con roles distintos que colaboran para resolver un proceso completo de forma autónoma.
  • Agente de recompra proactivo — monitorea el historial y contacta al cliente antes de que él recuerde hacerlo.
El RAG, el HITL y los flujos n8n que armaste hoy son exactamente la base sobre la que se construyen esos sistemas. Todo lo que construiste hoy se reutiliza en el programa.
